# 同名与去重规则

本文件只判断多个 Figma 文本节点能否共享同一个图层名称。它不生成文本条目、渲染值或外部身份。

## 边界

- 只在同一个匹配的 Figma 页面内比较节点，可以跨该页面的多个 `预览图/*` Frame。
- 不跨 Figma 页面共享新名称。
- 去重只使用当前 Figma 快照中可观察的证据：文本内容、占位符结构、有意义的原图层名、语义祖先、相邻标签、所属组件、组件变体和有意义的样式差异。
- 不读取或要求后端接口字段、Pagecenter 配置来源、Vue 运行时变量、代码数据绑定或其他外部来源。它们不可见不算证据不足，不得单独触发 `confirm`。
- 节点 ID 和视觉位置只用于定位、排序或最终裁决。自动生成的图层名、Frame 名称、当前可读 Key 和候选名称不能单独证明重复；有明确业务含义的原图层名可以作为语义证据。

## 比较信息

为每个候选构建仅供内部比较的 Figma 签名：

- `textSignature`：Unicode NFC 规范化后的 `characters`；CRLF/CR 统一为 LF；动态占位符统一记为 `{{}}`，保留数量、位置、换行、空格和标点。
- `styleSignature`：会改变文本视觉含义的局部颜色、字号和字重差异；没有局部差异时为空。
- `layerNameEvidence`：改名前有明确业务含义的原图层名；自动名称或已生成的可读 Key 不作为同义证明。
- `semanticContext`：由语义祖先、相邻标签、所属组件和组件变体直接体现的业务用途与状态。
- `placeholderSemantics`：能从上述 Figma 证据判断时，按顺序记录占位符含义；无法观察时留空。

签名只记录实际观察到的信息，不为后端字段、配置来源或代码绑定预留必填项。未观察到某项信息既不证明相同，也不证明不同；不得把空值或 `unknown` 本身当作 `confirm` 理由。

签名不得包含节点 ID、文件键、页面节点 ID、视觉顺序、候选名称、UUID 或任何外部数据。调用方已提供的 UUID 只能在分类与选名完成后附在结果中；缺少 UUID 不得改变 `exact`、`near` 或 `unique` 分类。

## 分类

### 可共享名称 `exact`

只有同时满足以下条件时才自动共享名称：

1. `textSignature` 相同。
2. 占位符数量和位置相同；双方都有可观察的占位符语义时，其含义和顺序也相同。
3. 有意义的原图层名、语义祖先、相邻标签、所属组件和组件变体没有表明不同用途或状态。
4. 不存在会改变文本含义的样式差异。
5. 文本固定部分本身足以表明同一用途，或至少有一项 Figma 上下文正向支持用途相同。只有占位符或内容过于泛化时，单凭结构相同不足以自动共享名称。
6. 不存在名称冲突。

### 近似重复 `near`

只有 Figma 内已观察到的证据互相冲突，或同一组证据支持多个会改变去重结果的合理解释时，才进入 `confirm`，例如：

- 有意义的原图层名支持同一用途，但组件或变体明确指向不同状态，且无法判断该状态是否影响文本身份。
- 相邻标签支持共享，语义祖先却支持拆分，且两类证据都可信。
- 已有合法名称与其他 Figma 语义证据冲突，保留或合并都会改变结果。

外部信息不可见、某项 Figma 上下文为空、或模型无法从通用页面模式猜出运行时来源，都不是 `near`，不得因此询问用户补充外部来源。

### 独立项 `unique`

满足以下任一条件时作为独立项命名，不进入 `confirm`：

- Figma 证据清楚表明用途、状态、占位符含义或有意义样式不同。
- 文本或占位符结构不同，且没有既有名称冲突需要裁决。
- 只有占位符或内容过于泛化，同时没有足够的 Figma 正向证据证明用途相同。
- 没有可共享名称的成员，也没有 Figma 内部证据冲突需要共同确认。

## 选择共享名称

对 `exact` 组按以下顺序选择一个名称：

1. 组内语义一致且合法的现有名称。
2. 同页面中相同语义组已经使用的合法名称。
3. 按命名规则生成的新名称。

若组内存在多个不同的合法名称，先判断是否有一个与当前 Figma 上下文更一致；无法确定时进入 `confirm`，不得仅按字典序或最短名称选择。

## 询问与汇报

近似重复或冲突必须列出：相关节点、当前名称、可辨认的 Figma 上下文、相互冲突的具体证据，以及用户需要确认的问题。问题必须能由用户裁决 Figma 中的语义或命名选择，不得要求追查后端接口、Pagecenter、Vue 或代码绑定。不得把近似重复报告为已去重。

正常的 `exact` 组无需逐组展开，除非多个节点将因此改成同一个名称，或用户明确要求查看同名判断。

## 幂等性

成功改名后再次扫描：

- `exact` 组继续共享同一名称。
- 已合法命名的 `unique` 项保持不变。
- 不因扫描顺序、Frame 折叠、隐藏或选中状态变化重新编号。
- 文本、样式或 Figma 语义上下文变化时重新分类；不得沿用已经失去依据的同名结论。
