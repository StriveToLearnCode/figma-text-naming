# 去重规则

以 Pagecenter 页面 ID 为边界，在同一页面的所有目标 `预览图/*` Frame 之间去重。重复组可以包含来自不同 Frame、组件或区域的节点，但不得跨 Pagecenter 页面分组。

不得根据 Figma 节点 ID、Frame 名称、视觉位置、当前图层名称或候选键判断节点是否重复。这些字段只能用于定位、排序或选键。

## 构建最终值

选择文本键之前，按以下顺序构建规范化后的 Pagecenter 最终值：

1. 将 Unicode 规范化为 NFC。
2. 将 CRLF 和 CR 统一转换为 LF。
3. 若文本包含真实 LF 换行，在 HTML 转义前删除其中字面量 `</br>` 标签；匹配时忽略大小写并允许标签内空白。以 LF 作为唯一换行来源，不得将该标签转义进最终值，也不得将其替换为额外换行。例如，`第一行</br>\n第二行` 归一化为 `第一行\n第二行`。
4. 使用命名规则中的 `normalizeDynamicPlaceholders`，将每个动态占位符转换为 `{{}}`，保留占位符的数量、位置和排列顺序。
5. 转义 HTML 特殊字符。
6. 仅当同一 `TEXT` 节点存在会影响 Pagecenter 最终展示的局部富文本差异时，使用最简 `span` 保留样式。
7. 规范化生成的 HTML。
8. 删除每行末尾的空白，保留内部空格、换行、从右到左的文本顺序和标点符号。

Pagecenter 最终值只使用通用 `{{}}`，不得改写为命名占位符。例如，运行时语义为“当前值 / 总值”时仍输出：

```text
{{}} / {{}}
```

不得输出 `{{current}} / {{total}}` 或 `{{当前值}} / {{总值}}`。

### 富文本规范化

普通文本直接输出经过 HTML 转义的纯文本，不添加标签。仅保留以下能影响最终展示的局部样式：

- `color`
- `font-size`
- `font-weight`

按以下规则规范化 HTML 和样式：

1. 十六进制颜色统一使用小写。
2. CSS 属性固定按 `color; font-size; font-weight` 排列。
3. 删除没有实际样式作用的 `span` 和不必要的整段包装标签。
4. 合并相邻且样式完全一致的 `span`。
5. 不输出空的 `style` 属性。
6. 不保留仅来自 Figma 编辑状态、不会影响 Pagecenter 展示的样式。

样式无法可靠转换时不得猜测；将节点归入 `confirm`。

## 记录占位符语义

为每个占位符按其在最终值中的出现顺序记录中文业务含义，例如：

```json
["当前值", "总值"]
```

占位符含义只能来自以下证据：

- 文本自身内容；
- 语义祖先和相邻文案；
- 组件或变体状态；
- 明确的字段名称；
- 明确的 Pagecenter 配置或运行时数据来源；
- 用户已确认的业务含义。

不得根据视觉位置、常见页面习惯或主观猜测推断。无法可靠判断时记录 `unknown`。`unknown` 只表示证据不足，不表示两个占位符的语义相同。

占位符数量必须等于 `placeholderSemanticSequence` 的成员数量。即使最终值相同，只要占位符语义或顺序不同，就不得自动合并。例如 `["当前值", "总值"]` 与 `["总值", "当前值"]` 不同。

占位符中文备注仅用于解释变量、构建签名和校验去重，不得写入文本条目的 `value` 或 `describe`。执行环境支持节点备注时可以写入备注；否则保留在内部组记录和用户确认信息中。

## 构建签名

为每个候选节点构建以下四项：

- `renderSignature`：规范化后的最终 HTML 或文本值，包含文本、占位符数量及位置、富文本样式、换行和标点。
- `plainSignature`：移除样式标签后的规范化纯文本，仍保留占位符数量和位置。它只用于发现近似重复，不得单独证明完全重复。
- `placeholderSemanticSequence`：按出现顺序记录的占位符中文业务含义列表。
- `semanticSignature`：由 `normalizedCharacters + semanticRole + stateVariant + dataSourceHint + placeholderSemanticSequence` 组成。

`semanticSignature` 的字段含义如下：

- `normalizedCharacters`：基础规范化后的原始文本结构，动态占位符统一表示为 `{{}}`，不含富文本样式。
- `semanticRole`：文本在运行时表达的业务含义，例如当前积分、剩余次数、奖励名称或活动倒计时。
- `stateVariant`：文本对应的业务状态或出现条件；没有状态差异时使用空值，无法确认时使用 `unknown`。
- `dataSourceHint`：预期 Pagecenter 配置值或运行时数据来源；没有可靠证据时使用 `unknown`。
- `placeholderSemanticSequence`：按实际出现顺序记录的占位符语义。

签名不得包含以下内容：

- Figma 节点 ID、文件键或页面节点 ID；
- Frame 名称；
- 当前键或候选键；
- 节点描述；
- 视觉顺序；
- 为去重生成的临时编号。

语义字段必须有文本、语义祖先、相邻文案、组件或变体状态、明确数据来源或用户确认作为证据。任一关键语义字段为 `unknown` 且缺少其他明确证据时，不得自动判定为完全重复；归入近似重复并标记为 `confirm`。

## 分类重复组

每个候选节点最终归入 `exact`、`near` 或 `unique`。

### 完全重复 `exact`

只有同时满足以下条件才自动合并：

1. `renderSignature` 完全相同；
2. `semanticSignature` 完全相同；
3. `placeholderSemanticSequence` 完全相同；
4. 归一化文本结构和占位符数量、位置完全一致；
5. 占位符业务含义及顺序一致；
6. 业务角色、展示状态或出现条件一致；
7. 相邻文案和语义祖先没有表明不同用途；
8. Pagecenter 配置或运行时数据来源一致；
9. 不存在未解决的键冲突。

不得仅因为 `characters`、`plainSignature`、`renderSignature`、当前图层名称、候选键或视觉外观相同就判定为完全重复。

完全重复组中的所有可编辑节点使用同一个规范键，并且只生成一个 Pagecenter 文本条目。例如，四个节点都渲染为 `بطاقة الهدية {{}}`，占位符都表示“奖励序号”，并且业务角色、状态、数据来源和样式一致，则共享 `reward/five-star-name`，不得生成 `reward/five-star-1-name` 到 `reward/five-star-4-name`。

### 近似重复 `near`

满足以下任一条件时归为近似重复：

- `plainSignature` 相同但 `renderSignature` 不同；
- `renderSignature` 相同但 `semanticSignature` 不同或无法确认；
- 最终值相同但占位符语义或顺序不同；
- 最终值相同但业务角色、展示状态或数据来源不同；
- 文本结构相近但占位符数量或位置不同；
- 文本结构相近但存在有意义的颜色、字号或字重差异。

近似重复不得自动合并。不得使用编辑距离、翻译相似度、视觉相似度、字符数量、位置接近、常见页面结构或模型主观判断来合并。

### 唯一项 `unique`

没有完全重复成员，也没有需要共同确认的近似重复候选时归为唯一项。`unique` 仍须通过键格式、语义完整性和冲突校验。

## 处理近似重复与冲突

将近似重复节点分别保留并放入 `confirm`，要求用户决定共用键、分别命名或补充业务语义、数据来源、占位符含义及顺序。提问必须列出阻止自动合并的具体差异，不得只说“语义可能不同”。

文本相同但业务语义不同的节点必须使用不同键。例如两个节点的最终值都是 `{{}} / {{}}`，但一个表示“当前积分 / 目标积分”，另一个表示“剩余次数 / 总次数”，则必须分别命名并加入 `nearDuplicates`。

同一个候选键不得对应不同的 `renderSignature`、`semanticSignature`、占位符语义顺序、业务角色、展示状态或数据来源。发生任一差异时加入 `conflicts`；不得用无意义编号掩盖冲突，应根据真实业务语义生成可区分的键。无法生成稳定语义键时标记为 `confirm`。

用户确认的业务信息可作为新证据。吸收确认后必须重新校验键格式、最终值、占位符数量及语义顺序、业务语义和页面内键冲突。用户明确确认的业务关系可以消除之前的 `unknown`，不得因确认前的不确定性重复阻止同一决定。

## 选择规范键

为通过全部校验、可以进入 items 的组选择规范键，包括：

完全重复组 exact；
唯一项 unique；
经用户确认并重新分类、校验通过的组。

每个 exact 组选择一个由所有成员共享的规范键；每个 unique 组选择一个独立规范键。

按以下顺序在首个适用层级停止：

已验证的固定兼容键。
与受控词表推荐键一致的有效 Figma 键。
受控词表推荐键。
由最高优先级业务域支持的有效 Figma 键。
由最高优先级业务域支持的新建议键。
最短且稳定的语义键。
仅当以上优先级完全相同时，使用稳定视觉顺序裁决：预览 Frame 顺序、从上到下、从左到右，最后使用节点 ID 保证排序稳定。

视觉顺序只能用于同优先级候选键之间的最终裁决，不得作为业务语义证据，也不得直接用于生成键名。

不得为了减少文本条目数量而复用语义不一致的键，也不得生成 text-1、label-2、xx-1、dynamic-text-3 等临时键。

## 生成 items

每个通过校验的完全重复组只输出一个文本条目：

```json
{
  "key": "progress/current-total",
  "value": "{{}} / {{}}",
  "describe": ""
}
```

不得虚构或输出其他 Pagecenter 元数据。占位符中文语义备注不得写入 `value` 或 `describe`。

`items` 表示当前页面最终可供 Pagecenter 后续流程使用的文本条目，而不是本次改名记录。它应包含：

- 本次成功改名的有效节点；
- 已经使用正确键名、无需改名的有效节点；
- 完全重复组去重后的唯一条目；
- 用户确认后通过全部校验的条目。

它不得包含：

- 尚未确认的近似重复节点；
- 未解决冲突、写入失败或回读失败节点；
- 无法确认业务含义或占位符语义顺序的节点；
- 无法确认配置来源且该不确定性会影响去重判断的节点；
- 仅因实例继承而无法确认最终键和值的节点。

每个 `items.key` 只能出现一次，同一个键不得对应多个不同的值或业务语义。

## 记录与汇报

在内部为每个组记录：

```json
{
  "type": "exact | near | unique",
  "memberNodeIds": [],
  "memberCurrentKeys": [],
  "renderSignature": "",
  "plainSignature": "",
  "semanticSignature": "",
  "placeholderSemanticSequence": [],
  "canonicalKey": "",
  "canonicalKeyReason": "",
  "item": null,
  "differences": []
}
```

未解决的 `near` 组或冲突组可以让 `canonicalKey` 和 `item` 为空。`differences` 必须记录阻止自动合并的文本、样式、状态、数据来源或占位符语义差异。

默认不展示普通 `unique` 组、未影响条目数量且校验正常的 `exact` 组或内部签名。仅在以下情况展示分组明细：

- 多个节点合并为一个条目并减少了 `items` 数量；
- 近似重复、占位符语义差异或冲突需要用户确认；
- 用户明确要求查看全部去重明细。

展示完全重复组时，至少说明规范键、成员节点 ID、最终值、占位符中文备注、减少的条目数和合并理由。展示近似重复或冲突时，至少说明相关节点、当前名称、最终值、占位符中文备注、业务语义、阻止合并的差异和需要用户确认的具体问题。不得将近似重复、跳过节点或未解决冲突混入成功合并结果。

## 保证幂等性

成功执行后再次扫描同一页面，应满足：

- 已完成命名的节点不再产生新改名计划；
- 完全重复组继续使用相同规范键；
- 占位符中文备注及顺序保持一致；
- `items` 的键和值保持一致且不重复；
- 不因图层名称变化、节点扫描顺序、Frame 折叠、隐藏或选中状态改变去重结果。

文本内容、业务状态、数据来源或占位符语义发生变化时，重新计算签名并重新分类。
