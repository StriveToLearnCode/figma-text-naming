# 去重规则

本文件只判断同一匹配 Figma 页面内的候选文本应共享名称、分别命名还是等待确认。可跨该页面的多个 `预览图/*` Frame 比较，不跨页面建立共享组。

## 可观察证据

去重只使用当前 Figma 快照能直接观察到的信息：

- 文本内容；
- 动态占位符的数量、位置和顺序；
- 写回前有明确业务含义的图层名称；
- 语义祖先和相邻文案；
- 所属组件、组件或变体状态；
- 按需补查后确认会改变文本含义或用途的样式差异。

节点 ID、页面/文件 ID 和视觉位置只用于定位、排序或稳定裁决。自动图层名、候选 Key、空值或未知项不证明相同或不同。

## 内部比较

为候选构建仅供比较的签名：

- `textSignature`：对 `characters` 做 Unicode NFC 规范化，CRLF/CR 统一为 LF；把每个动态占位符统一记为 `{{}}`，保留数量、位置、顺序、换行、空格和标点。
- `layerNameEvidence`：写回前明确描述业务含义的中文图层名；自动名称和已生成 Key 不作为同义证明。
- `semanticContext`：语义祖先、相邻文案、组件、所属对象和变体状态直接体现的用途。
- `styleSignature`：默认留空；仅在相同文本与语义需要判断能否完全复用、文本存在相关多段样式，或用户明确要求时补查。只记录“相同”或“有意义差异”，纯装饰差异不强行拆分；颜色只能辅助语义证据，不能单独拆组或编号。
- `placeholderSemantics`：能够从上述 Figma 证据判断时，按出现顺序记录占位符含义；无法观察时留空。

这些签名默认不输出。第一阶段不读取 `styleSignature`；需要上下文或样式时，把相关节点与所需字段合并到唯一一次第二阶段批量查询中，不得逐节点重复查询。只有 `confirm`、`failed`、需要解释的 `skip` 或用户明确要求明细时，才展开相关节点 ID 和具体差异。

## 分类

### `exact`

文本结构、可观察语义和用途一致时归为 `exact`，共用一个无编号 Key。必须满足：

1. `textSignature` 相同，且占位符数量、位置和顺序一致。
2. 双方可观察到占位符含义时，含义和顺序也一致。
3. 图层名证据、语义上下文、所属对象、组件和状态没有表明不同用途。
4. 按需比较的局部样式相同，或不存在需要样式裁决的条件。
5. 固定文案足以说明同一用途，或至少有一项 Figma 上下文正向支持共享。

完全相同的业务含义和用途必须共享同一个 Key，不得为成员增加编号。多个文本都只显示 `xx` 不构成共享证据。

### `near`

文本相同或相近，但按需观察到的样式、语义、状态、占位符含义或所属对象存在差异时归为 `near`，不得自动合并。

- 差异清楚且各自含义可确定：分别生成语义 Key。
- 多个节点具有共同语义但表示不同字段，且没有更短稳定的语义词可区分：使用共同语义加两位编号。
- 证据相互冲突，或支持多个会改变命名/去重结果的合理解释：标为 `confirm`。

例如当前积分和剩余次数是不同语义，应分别命名；两个不同戒指盒的开启次数属于同类不同项，只补查这两个节点，并可编号或使用 Figma 中可确认的 `158`、`388` 稳定标识。

### `unique`

没有重复或近似候选时归为 `unique` 并独立命名。以下情况也直接作为独立项，不因无法共享而进入 `confirm`：

- 文本或占位符结构明显不同，且没有既有名称冲突。
- Figma 证据清楚表明用途、状态、占位符含义或有意义样式不同。
- 只有占位符或内容过于泛化，且没有正向证据证明与其他节点用途相同；若该节点自身语义也无法命名，才另标 `confirm`。

## 名称与冲突

- `exact` 组优先保留组内语义一致的合法名称，其次复用同页相同语义组的合法名称，最后生成新 Key。
- 同组存在多个不同合法名称时，选择与当前 Figma 证据最一致者；无法判断时进入 `confirm`。
- `near` 的编号遵循命名规则：保留已有合法编号，新增节点使用组内未占用的最小两位编号，不按扫描顺序重排。
- 相同 Key 对应不同文本结构、用途、状态或所属对象时是冲突，不得静默合并，也不得追加节点 ID 解决。

## 汇报与幂等性

- 默认把每个建议名称压缩为一行，只显示建议名称、节点数、中文含义和状态。`exact` 组使用 `shared`，不列成员节点；`near` 的稳定编号使用 `numbered`；普通待改项使用 `rename`；当前已正确的固定兼容键使用 `skip`。
- `confirm` 必须列出相关节点、当前名称、可辨认的 Figma 上下文、冲突证据和用户需要裁决的问题。
- 成功改名后再次扫描，`exact` 组继续共享，`near` 编号保持，`unique` 名称保持。
- 文本、按需观察的样式或 Figma 语义上下文变化时重新分类，不沿用已经失去依据的结论。
