# Scope 与动态文案分类

本文件负责确定处理范围、完整扫描 Text，并把每个 Text 分类为 `rename / keep / skip / confirm`。名称格式和语义写法以 [命名规范](naming-standard.md) 为准。

## 1. 确定 Scope

默认范围：

1. 链接直接指向 `预览图/*` 或 `弹窗/*` 时，以该节点作为 Scope。
2. 链接指向包含多个页面或弹窗的上层节点时，只检查其直属子节点中的 `预览图/*` 和 `弹窗/*`，不递归寻找更深层的同类节点。
3. 用户明确指定某个非 `预览图/*`、非 `弹窗/*` 节点时，以该节点作为 Scope，不扩展到其他区域。
4. 多个节点链接分别确定 Scope，并按 `nodeId` 去重；用户明确指定的节点优先于自动发现范围。

确定 Scope 时不默认扫描整页，也不从祖先、兄弟节点或其他画布区域补充范围。

以下区域默认排除，遍历遇到后立即剪枝，不读取其后代 Text：

- `母组件`、`母组件（...）`、组件库和设计复用区
- `切图/*`、示意图、效果预览、标注和设计说明
- `动效`、动画、PAG、SVGA、SVG 展示或制作区

只有用户明确指定这些区域或其中节点时，才将其作为独立 Scope。无法可靠确定 Scope 时不要猜测；这会改变写入目标，必须先取得更具体的节点链接。

## 2. 完整扫描

确定 Scope 后向下遍历全部 Text。不得使用 placeholder、`x/xx/XXX/{{}}`、当前名称、正则或文案内容预筛候选。

每个 Text 至少记录：

- `nodeId`
- 节点路径
- 当前 `node.name`
- 原始 `characters`
- 所属预览图或页面
- 判断所需的父级、组件、布局和绑定信息

可以读取父级结构、同构节点、Instance / Component 关系、Variable、property 和 binding 作为证据，但单一证据不直接决定是否命名。

## 3. 运行时字段边界

命名对象是最终由运行时直接消费的完整 Text 文案字段，不是文案内部的参数，也不是列表项或业务实体的属性本身。

1. 一个 Text 已承载完整文案模板时，以整个 Text 为边界，不拆分 placeholder、数字、昵称、礼物名等参数。
2. Text 同时含固定文字和一个或多个运行时参数，只要整体承担明确 UI 文案职责，就按整个 Text 判断；参数数量和业务类型不改变边界。
3. 同一个稳定的任务、条件、状态或提示位置会根据任务、配置、用户操作、时间或业务状态替换内容时，属于运行时文案字段，即使设计稿展示的是完整字面量。
4. 当前配置已确定具体文字不代表固定文案；只有能确认运行时始终不会替换，才按固定内容处理。
5. 整个 Text 只是单个运行时值时：
   - 位于重复或同构列表项中，只是昵称、数量、积分、奖励名等内部属性：`skip`
   - 位于非重复 UI 中，是职责明确的独立稳定展示字段：进入命名判断
   - 无法区分：`confirm`

placeholder、Variable、property、binding、同构槽位差异和状态变化只是运行时证据，不是自动命名条件。不得因为没有 placeholder 就排除，也不得因为出现 placeholder 就直接命名。

## 4. 默认不命名的内容

- 固定标题、按钮、标签、规则说明和不会被替换的普通文案；榜单规则即使支持运营配置，也按规则说明处理
- 榜单条目和“我的排名”中的名次、积分、分数、昵称、成员名、队名、家族名和占位状态，无论页面只展示一条还是形成重复列表
- 奖励或道具展示位中的道具名称、数量和倍率，无论页面只展示一个还是形成重复列表
- 其他重复列表项中的实体属性
- 装饰、示例、标注和设计说明
- 仅因 Variant、显隐或组件切换而变化，但 Text 内容不会被替换的文字

非榜单、非道具且不属于重复实体属性的独立运行时字段，继续按运行时字段边界判断。

## 5. 已有名称与分类

已有 `文案/...` 名称不代表已经正确。仍需检查：

- 当前 Text 是否确实属于运行时管理字段；命中排除项时仍为 `skip`，并报告“不应命名”
- 字段职责和业务语义是否明确
- 名称是否符合 [命名规范](naming-standard.md)
- 参数边界是否正确

最终分类：

- `rename`：属于动态文案，尚未命名或已有名称需要修改
- `keep`：属于动态文案，已有名称与当前语义、格式一致
- `skip`：不需要运行时文案命名
- `confirm`：字段职责、运行时性质、业务语义或最终复用关系存在实质歧义

`parameterized` 只描述参数边界，不改变 `rename / keep`。参数边界不完整时单独标记“待确认”；不要仅因缺少接口、代码或数据源把字段改为 `confirm`。

## 6. 置信度和写回边界

- `high`：placeholder、binding、Variable、明确结构职责、同构槽位或稳定上下文共同支持
- `medium`：字段职责和业务语义基本明确，但运行时证据较弱
- `low`：存在多个合理字段含义，或复用关系、运行时性质无法区分

`low` 且会影响是否命名或最终名称时使用 `confirm`，不要硬猜。

`apply` 允许存在与其他字段无关的 `confirm`，只写回已确定的 `rename`；`repair` 只修复能够确定目标名称的历史错误。Scope 不完整、存在未分类 Text 或写入范围仍有实质歧义时，禁止写回。
