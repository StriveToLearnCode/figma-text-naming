# 命名规则

## 候选项检测

使用文本节点的 `characters`，不使用当前图层名称：

```js
const dynamicPlaceholder = /(^|[^A-Za-z0-9])(?:[xX]{2,}|X)(?=$|[^A-Za-z0-9])/;
const isCandidate = dynamicPlaceholder.test(node.characters);
```

该表达式可匹配 `xx时xx分`、`xxxx/100`、包含 `XX` 的阿拉伯语文本及独立大写 `X`，但不匹配 `1x`。当前名称合法的候选仍要扫描，用于复核语义、冲突和去重关系。

## 名称格式

```js
const semanticTextKey = /^[a-z][a-z0-9]*(?:-[a-z0-9]+)*\/[a-z][a-z0-9]*(?:-[a-z0-9]+)*$/;
```

格式为 `<business-domain>/<semantic-key>`，所有路径段使用小写英文 kebab-case，例如 `reward/name`、`ring/open-count`、`task/progress`。

- 业务域描述稳定业务对象或模块，不描述页面位置。
- 语义部分只表达字段核心含义，优先控制在 1 至 3 个简短英文词内。
- 只有删除某个词会导致字段含义无法区分时才保留该词。
- 不把完整图层上下文、位置、状态和对象全部翻译进名称。
- 不使用 `value`、`text`、`label` 等空泛词，也不使用颜色、坐标、Frame 序号或中外文音译。

正则匹配只是最低条件。业务域、语义、编号和共享关系也必须符合本文件及去重规则。

## Figma 语义证据

命名依据只来自当前目标 Figma 页面的可观察快照，按以下顺序使用：

1. 完整文本及占位符在文本中的数量、位置和顺序。
2. 写回前有明确业务含义的图层名称。
3. 最近的具名语义父节点或祖先。
4. 相邻标签和兄弟文案。
5. 所属组件、组件或变体状态。
6. 同页同语义组中已由上述证据确认的合法名称。

`Frame 123`、`Group 8`、`板块4`、`Text 128`、`数字`、`xx` 等自动或空泛名称不构成语义证据。只有占位符且上下文不能说明含义时进入 `confirm`。

首次扫描只使用文本、写回前名称和精简 `parentPath`。直接祖先、相邻文案、组件、变体和局部样式只在最小字段不能解决实际歧义时补查；所有待补查节点合并成一次批量查询。

样式仅在判断相同文本与语义能否完全复用、文本存在可能影响复用的多段样式，或用户明确要求时读取。样式结果只需区分“相同”与“有意义差异”。颜色差异只能作为辅助证据，不能单独决定语义、业务域或编号。

## 选择顺序

1. 当前名称格式合法、足够简短，且语义、用途、编号与去重关系一致：保留。
2. 同页存在完全相同业务含义和用途的合法名称：复用。
3. 按词典生成最短且足以区分含义的新名称。
4. Figma 证据不足或冲突、存在多个合理解释：进入 `confirm`。

已有名称只是一项待复核证据，不能反向证明语义正确。已有 `txt/progress` 等合法短名称可在符合通用规则时保留；若与可观察语义不一致则进入 `confirm`。用户明确指定名称时，也必须通过格式、当前页面内冲突和语义一致性校验；该指令不作为其他节点的命名证据。

## 编号

优先使用无编号名称。完全相同的业务含义和用途共用同一个名称，不编号。

只有多个节点有明确共同语义、实际表示不同字段，并且没有更短稳定的语义词可区分时，才在共同语义后加编号：

```text
reward/name-01
reward/name-02
ring/open-count-01
ring/open-count-02
```

- 不得因为多个文本都显示 `xx` 就建立编号组。
- 当前积分和剩余次数不是同类，应分别使用 `rank/score`、`lottery/count` 等语义名称。
- 两个不同戒指盒的开启次数属于同类，可使用 `ring/open-count-01`、`ring/open-count-02`。
- 已有合法且语义正确的编号尽量保留。新增节点使用组内未占用的最小两位编号，不因扫描顺序变化重排。
- 数字前必须有共同语义；禁止 `txt/01`、`txt/02`、`text-01`、`Page_Module_txt01`。

## 冲突与稳定性

- 相同名称对应不同文本结构或不同业务用途时是冲突，不得静默复用或用节点标识消除冲突。
- 格式正确但语义错误、过长或共享关系错误的名称仍需确认。
- 不得因扫描顺序、图层移动、Frame 折叠、隐藏或新增无关节点重命名已有合法项。
- 首次分配需要排序时，依次使用 Frame 页面顺序、层级/视觉顺序和节点标识；排序只用于稳定裁决，不进入名称。
