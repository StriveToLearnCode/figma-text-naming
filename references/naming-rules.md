# 命名规则

## 适用边界

本文件只约束 Figma 翻译页面中的动态文本图层，不约束切图、插件控件或代码标识符。

## 候选项检测

使用文本节点的 `characters`，不使用当前图层名称：

```js
const dynamicPlaceholder = /(^|[^A-Za-z0-9])(?:[xX]{2,}|X)(?=$|[^A-Za-z0-9])/;
const isCandidate = dynamicPlaceholder.test(node.characters);
```

该表达式可匹配 `xx时xx分`、`xxxx/100`、包含 `XX` 的阿拉伯语文本及独立大写 `X`，但不匹配 `1x`。

## 合法名称

```js
const readableTextKey = /^[a-z][a-z0-9]*_[a-z][a-z0-9]*_txt\d{2,}$/;
```

格式为 `Page_Module_txtNN`，例如 `tab1_progress_txt01`：

- `Page`：稳定的页面、页签或状态范围短标识，例如 `tab1`。
- `Module`：页面内稳定模块短标识，例如 `progress`。
- `txtNN`：模块内文本序号，至少两位。

图层名只包含这个名称。不得加入路径前缀、节点 ID、文件键、随机值或外部系统身份。

正则匹配不等于语义合法。以下条件必须同时成立：

1. 格式匹配 `readableTextKey`。
2. Page 和 Module 与当前 Figma 上下文一致。
3. 相同名称没有对应不同文本结构或明显不同业务语义。
4. 名称不是从不稳定的位置、自动生成容器名或节点 ID 推导而来。

## Figma 语义证据

按以下顺序判断 Page、Module 和文本用途：

1. 当前文本的完整含义。
2. 当前文本图层的有意义旧名称。
3. 最近的具名父节点或祖先节点。
4. 相邻标签和兄弟文本。
5. Figma 中明确的组件、变体或状态名称。
6. 同一语义组中已经合法命名的节点。
7. 视觉顺序，仅用于分配编号或同优先级候选的稳定裁决。
8. 用户明确确认的业务含义。

拒绝 `板块4`、`Frame 123`、`Group 456`、`Text 128`、`数字`、`xx` 等自动名称作为语义证据。文本只有占位符且上下文无有效语义时，必须进入 `confirm`。

不得要求或利用外部配置、代码调用、接口字段或持久化身份来完成 Figma 命名。调用方已经提供 UUID 时，只能在命名判断完成后将其作为可选元数据原样附带；UUID 缺失不得产生 `confirm` 或阻止改名，UUID 的创建与映射持久化交给其他 Skill。

## 稳定选择顺序

为单个候选或可共享名称的节点组按以下顺序选择名称，并在首个适用层级停止：

1. 当前图层名合法，且与 Figma 上下文和业务语义一致：保留。
2. 同一目标页面中存在语义、状态、文本结构和样式约定一致的合法名称：复用。
3. 根据已有 Figma 页面与模块命名选择 Page 和 Module，并分配新的 `txtNN`。
4. Page、Module、文本用途或复用关系无法确定：进入 `confirm`。

分配新编号时：

- 保留所有已有合法编号，不重排、不补洞。
- 同一 `Page_Module` 新增项使用当前最大编号加一。
- 首次批量命名且没有已有编号时，按 Frame 顺序、从上到下、从左到右分配；节点 ID 只作最终排序裁决。
- 符合同名条件的节点共享名称，不增加编号。

## 冲突处理

- 同名节点的文本结构、语义角色、状态或有意义样式不同：标记冲突，不得静默复用。
- 文本相同但没有足够的 Figma 正向证据证明用途相同：分别命名，不得仅凭位置合并；只有可观察的 Figma 证据互相冲突、需要用户裁决时才进入 `confirm`。
- 已有合法名称与 Figma 上下文明显冲突：进入 `confirm`，提供保留或重命名的依据。
- 不得为消除冲突而追加节点 ID、随机后缀或重排已有编号。
- 用户提供自定义名称时，仍需校验格式、页面内冲突和语义一致性。
