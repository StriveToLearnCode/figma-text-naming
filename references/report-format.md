# 命名报告格式

最终报告先给结论，再给完整表格。`apply` 模式先在内部生成和校验同一份清单，再继续写回；最终报告反映实际结果，不能把报告当成等待确认的暂停点。

## 1. 明细表

| nodeId | 文案原文 | 当前名称 | 语义判断 | 建议完整名称 | 参数化 | 命名校验 | 规则依据 | 置信度 | 处理 |
| ------ | -------- | -------- | -------- | ------------ | ------ | -------- | -------- | ------ | ---- |

`处理` 只能是：

- `rename`：需要命名或已有名称需要修改
- `keep`：已有名称符合语义和规范
- `skip`：不需要运行时文案命名
- `confirm`：关键判断无法确定，需要用户确认

需要展示名称时始终使用完整 Figma 图层名 `文案/${business-domain}/${semantic-key}`，不要只给裸 key。

## 2. 汇总

报告末尾必须包含：

- 本次 Scope 和实际扫描的 Text 总数
- `rename / keep / skip / confirm` 数量
- 默认未纳入 Scope 的区域及排除原因
- 名称复用与重名检查结果
- 未分类 Text 数
- 名称格式失败数
- 业务域不合规数
- semantic-key 不合规数
- 参数边界待确认数
- 所有命名校验失败项的 `nodeId / 当前名称或建议名称 / 失败原因`
- 所有低置信度和 `confirm` 项
- `apply / repair` 中实际成功的 `nodeId: oldName -> newName`
- 写回跳过或失败项及原因

最终必须满足：

```text
Text 总数 = rename + keep + skip + confirm
```

## 3. 统计口径

`skip` 只统计已进入当前 Scope、经过判断后确认无需命名的 Text。

未进入 Scope 的母组件、切图区、动效区、标注和设计说明等不计入 `skip`，只按排除原因汇总，不能把未扫描节点数量混入分类结果。

Scope 内每个 Text 必须得到且只得到一种处理结果。`apply / repair` 写回失败的 `rename` 项必须明确标记失败，不能报告为成功。
