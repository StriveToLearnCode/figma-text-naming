# 命名报告格式

最终报告先给结论，再给精简明细表和必要的异常说明。`apply` 模式先在内部生成和校验同一份完整清单，再继续写回；最终报告反映实际结果，不能把报告当成等待确认的暂停点。

## 1. 最终明细表

最终返回给用户的主明细表只保留以下 5 列，避免把内部判断过程混入主结果：

| 节点位置 | 原始文案 | 命名结果 | 置信度 | 处理结果 |
| -------- | -------- | -------- | ------ | -------- |

主明细表默认只展示实际发生或需要处理的条目：已完成命名、建议命名、待确认和失败项。`保持不变`、`无需命名`等没有操作的条目不逐行展示，只在“汇总”中统计；用户明确要求完整审计时，才追加包含全部条目的明细表。

`原始文案`对所有展示行都是必填，必须保留该节点完整的 `characters`；待确认、未写回（含写回失败）的条目尤其不能省略。确实为空时明确写 `（空文本）`，不得留空或用其他节点的文案代替。

“命名结果”的填写规则：

- 已执行写回：填写 `已写回：文案/${business-domain}/${semantic-key}`；写回失败填写 `写回失败：原因`。
- 保持现有名称：填写当前名称。
- 仅提供建议：填写 `建议名称：文案/${business-domain}/${semantic-key}`，不得暗示已经写回。
- 无需命名：填写 `无需命名`；如已有名称以 `文案/` 开头，保留该名称。
- 无法确定：填写 `待确认`，不猜测名称。

语义判断、参数化、规则依据和命名校验仍须在内部清单中完整保留；只有命名校验失败、写回失败或需要用户确认时，才在最终报告中追加对应原因。

最终报告中的 `处理结果` 使用中文；内部清单仍使用以下固定枚举：

- `rename`：`已完成命名`（写回模式）或 `建议命名`（只读模式）
- `keep`：`保持不变`
- `skip`：`无需命名`
- `confirm`：`待确认`

需要展示名称时始终使用完整 Figma 图层名 `文案/${business-domain}/${semantic-key}`，不要只给裸 key。

### 节点定位链接

节点位置统一显示为可点击的 Figma 链接，例如 `[1:2](https://www.figma.com/design/FILE_KEY/file-name?node-id=1-2)`。链接基于用户提供的文件 URL，将目标 `nodeId`（`1:2` 转为 `1-2`）写入或覆盖 `node-id` 参数；没有文件 URL 时显示裸 ID，并说明无法生成定位链接。

## 2. 汇总

报告末尾必须包含：

- 本次 Scope 和实际扫描的 Text 总数
- `已完成命名 / 保持不变 / 无需命名 / 待确认` 数量
- 默认未纳入 Scope 的区域及排除原因
- 名称复用与重名检查结果
- 未分类 Text 数
- 名称格式失败数
- 业务域不合规数
- semantic-key 不合规数
- 参数边界待确认数
- 所有命名校验失败项的可点击 `nodeId / 当前名称或建议名称 / 失败原因`
- 所有低置信度和待确认项
- 实际成功写回的可点击 `nodeId: oldName -> newName`
- 写回跳过或失败项及原因

最终必须满足：

```text
Text 总数 = rename + keep + skip + confirm
```

## 3. 统计口径

`skip` 只统计已进入当前 Scope、经过判断后确认无需命名的 Text。

未进入 Scope 的母组件、切图区、动效区、标注和设计说明等不计入 `skip`，只按排除原因汇总，不能把未扫描节点数量混入分类结果。

Scope 内每个 Text 必须得到且只得到一种处理结果。`apply / repair` 写回失败的 `rename` 项必须明确标记失败，不能报告为成功。
