# Figma 特效文本命名 Skill 使用文档

用于检查或批量修改活动设计稿中的动态文本图层名称，为含 `xx`、`XX` 等占位符的文本生成稳定的业务 Key 和完整中文含义。

## 调用格式

```text
$figma-text-naming
<Figma Design 节点链接>
<扫描范围或业务背景>，<执行要求>
```

建议提供带 `node-id` 的 Figma Design 链接，并选中需要处理的页面、Section、Frame 或文本节点。未提供 `node-id` 时会扫描文件内全部可访问页面。

## 执行模式

| 需求写法                   | 结果                         |
| -------------------------- | ---------------------------- |
| “扫描一下”“预览”“去重”   | 只读分析并输出命名建议       |
| “命名一下”“批量改名”       | 分析通过后写回 Figma         |
| “仅生成清单”“不要修改”     | 只输出命名建议               |
| “检查现有命名”             | 只读审核，不修改             |
| “审核并修复”               | 保留合规名称，修复其余名称   |

> 默认只读。只有明确要求“命名”“改名”“写回”或“修复”时才会修改 Figma。

## 使用示例

### 只读扫描

```text
$figma-text-naming
https://www.figma.com/design/xxx/activity?node-id=100-200

扫描这个 Frame 中含 xx/XX 的动态文本，生成命名清单，不要修改 Figma。
```

### 直接改名

```text
$figma-text-naming
https://www.figma.com/design/xxx/activity?node-id=100-200

按业务语义命名这些动态文本并直接写回 Figma。
```

### 跨区域去重

```text
$figma-text-naming
https://www.figma.com/design/xxx/activity?node-id=300-400
https://www.figma.com/design/xxx/activity?node-id=500-600

合并扫描同一页面的两个区域，相同文字且相同样式的文本共用一个 Key，只生成清单。
```

### 审核并修复

```text
$figma-text-naming
https://www.figma.com/design/xxx/activity?node-id=700-800

审核现有动态文本命名，符合规范的保留，不符合规范的直接修复。
```

## 输入建议

为提高命名准确率，建议说明：

- 处理范围：整个文件、指定页面、Section、Frame 或文本节点
- 业务背景：抽奖、排行、奖励、任务、充值等稳定业务对象
- 占位符含义：次数、余额、排名、时间、进度或状态
- 样式关系：相同文案是否属于同一字段的不同视觉版本
- 是否允许直接写回 Figma

## 扫描范围

默认扫描链接选中节点本身及其全部后代 `TEXT`，包括隐藏节点，并识别：

- `xx`、`xxx`、`xxxx` 等连续占位符
- 独立的 `XX` 或大写 `X`
- 文案中出现多个占位符的动态文本
- 当前名称已经合法但仍需复核语义和去重关系的候选

默认不会纳入：

- 链接已限定节点时的父级、同级和范围外节点
- `1x`、`box`、`extra` 等不符合候选规则的普通字符
- 跨 Figma 页面自动去重
- 实例继承或只读节点的直接写回

同一页面内，本次选中的多个扫描根节点可以共同去重。只有规范化文字和有效文字样式都完全一致时才共用一个名称。

## 输出结果

报告会列出：

| 字段         | 说明                                           |
| ------------ | ---------------------------------------------- |
| `nodeId`     | Figma 节点 ID                                  |
| 当前名称     | 修改前的图层名                                 |
| Figma 文本   | 占位符统一显示为 `{{}}` 的完整文案             |
| 中文含义     | 忠实保留数量、时间、条件和否定关系的完整含义   |
| 建议名称     | 完整的 `<business-domain>/<semantic-key>` Key  |
| 命名校验     | 格式、语义、去重、样式编号和冲突检查结果       |
| 语义和依据   | 业务对象、字段含义及可观察证据                 |
| 置信度       | `high`、`medium` 或 `low`                      |
| 处理         | `rename`、`keep`、`skip` 或 `confirm`          |

写回完成后还会提供成功、跳过和失败数量、去重分组、名称冲突、完整性检查结果，以及可用于回滚的 `old -> new` 清单。命名校验覆盖 `rename`、`keep`，以及已有候选名称但被标记为 `skip` 或 `confirm` 的节点。

## 注意事项

- 只支持 Figma Design，不支持 FigJam、Slides 或 Make。
- 直接写回需要 Figma 编辑权限；没有权限时只输出建议。
- Skill 只修改图层名称，不修改文字内容、位置、尺寸、样式或组件关系。
- 写回期间不要同时手动修改目标图层名称或文本内容。
